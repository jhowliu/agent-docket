# Workbench preview

Scope: conversation preview of the terminal workbench. Mode: Operate. All runs, commands, timestamps, source snippets and outcomes are synthetic. No provider or external actions are connected.

## Direction contract

THESIS: Put the whole team and the next human decision on one screen, with an agent roster above the selected Run. The user pinned Noopher-AI/oat-agents as the visual reference and supplied its exact URL.

OWN-WORLD: Terminal typography, restrained cyan structural emphasis, fine neutral rules, compact rows, amber waiting states and readable secondary text. Use a native monochrome font because the product is a terminal interface. Follow light/dark appearance; the dark source reference is the primary craft reference.

STORY: Scan three projects, choose a Run, inspect Live/Diff/Timeline/Evidence, answer or approve without opening a provider CLI. A response visibly moves from accepted to delivered in a simulation.

FIRST VIEWPORT: Compact title and demo indicator, all/pending controls, six agent rows, then the selected Verify Run with tabs and a command approval action. Composer and keyboard hints follow. At narrow widths, the roster reflows into labeled rows and actions remain reachable.

FORM: User-pinned oat-agents roster/detail grammar; seed not applicable to this reference-led preview. Build directly as an inspectable local interaction preview; no standing image-first/code-first workflow preference has been set. Reference: https://github.com/Noopher-AI/oat-agents and its docs/assets/tui-demo.svg, captured at output/oat-reference.png.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Signature interaction: select a waiting Verify Run, approve once, see acceptance followed by simulated delivery while the global pending count decreases. Reject and PM-answer flows are available independently. No entrance animations or perpetual spinners.

Open decisions: actual terminal density and shortcuts can change after the preview; real provider capabilities, environment and authentication remain unimplemented.
